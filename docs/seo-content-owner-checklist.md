# Данные, которые нужны владельцу сайта для SEO/GEO/AEO

## Реальные кейсы

Публичный реестр кейсов оставлен пустым, пока нет подтверждённых фактов. Для каждого из 5–10 кейсов CMS должна передать:

- `slug`, публичный заголовок и точный `serviceSlug` существующей услуги;
- город, регион, отрасль, тип и категорию объекта;
- исходную задачу, полученные данные, перечень выполненных работ и проверяемый результат;
- сроки, дату завершения и измеримые показатели без маркетинговых преувеличений;
- профиль исполнителя и отдельного проверяющего эксперта;
- нормативные источники и дату экспертной проверки;
- разрешение назвать клиента либо признак анонимизации;
- фотографии проекта с осмысленным `alt`, фактическими `width` и `height`;
- связанные статьи (`relatedArticleSlugs`).

Кейс публикуется только при `published=true`, `reviewStatus=APPROVED` и наличии подтверждённых экспертов. Черновики, заглушки и неподтверждённые результаты не индексируются.

## Региональная информация

Для дальнейшего расширения региональных страниц нужны факты по каждой паре «город + услуга»: реальные условия выезда, доступные виды работ, отраслевые особенности, подтверждённые сроки логистики и ссылки на реальные кейсы. Нельзя заменять эти сведения перестановкой одинаковых шаблонных фраз.

## Компетенции и документы

Для публикации аккредитаций, лицензий и разрешений нужны читаемые копии, номер, владелец, кем и когда выдан документ, срок действия и область применения. Пока реквизиты не подтверждены, интерфейс не называет документ действующим.

## Фото

Нужны собственные фотографии лаборатории, оборудования и выполненных проектов. Для каждого файла: право на публикацию, краткое описание сцены, город/проект (если можно раскрывать), дата съёмки и оригинал достаточного разрешения. После получения изображения проходят генерацию WebP/AVIF и проверку `alt`, размеров и наличия файла после сборки.
