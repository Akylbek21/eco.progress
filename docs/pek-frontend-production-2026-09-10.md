# Frontend ПЭК: доработка 10.09.2026

Итог: frontend исправлен, но полный сценарий пока **не готов к production** из-за ограничений текущего backend-контракта и отсутствия проверки на авторизованном стенде. Backend не изменялся. Существовавшие до работы изменения реестров и документов сохранены.

## Реализовано

- Точки мониторинга: форма широты/долготы отправляет `coordinates: "latitude, longitude"`. Проверяются диапазоны −90…90 и −180…180, формат числа и полнота пары; нулевые координаты сохраняются. После 409/412 требуется заново открыть актуальную запись. Ошибка удаления видна пользователю.
- Реестры выбросов, выпусков сточных вод и отходов доступны во вкладке «Реестры» программы. Просмотр, создание, редактирование и удаление используют реальные endpoints. Сохранены все поддерживаемые поля: оборудование, эффективность, часы, лимиты, единицы, сроки, площадки, описание и порядок. Добавлена валидация координат реестров.
- Движение отходов доступно в отчёте: начальный/конечный остаток, образование, передача, удаление, получатель, БИН и примечание; backend-расхождение баланса показывается без автоматической подмены остатка. POST-upsert существующей строки использует её версию в If-Match.
- В форме позиции контроля четыре селектора вместо ручного ввода ID: точка, источник выбросов, выпуск, отход. Загружаются только реестры текущей программы и точки её направлений; есть загрузка, отсутствие записей, недоступная связь и повтор загрузки после API-ошибки.
- Подключён `GET /api/pek/programs/{id}/readiness`. В обзоре показываются серверные причины блокировки, прогресс и счётчики реестров. Переходы ведут к разделам исправления. Выбранная вкладка сохраняется в URL. Добавлены прямые переходы к редактированию позиций, показателей и мероприятий.
- Сдача переименована в «Отметить отчёт как сданный». Интерфейс явно описывает ручную отметку, не обещает отправку в госорган и не представляет ACCEPTED/REJECTED как автоматический внешний ответ.
- Роль сама по себе не предоставляет права на изменяющие действия ПЭК. Используются явные `user.permissions` и серверные `availableActions`/флаги ресурса. Для просмотра отсутствие массива `permissions` трактуется как неизвестное состояние, поскольку текущий `/auth/me` его не возвращает: пункт ПЭК остаётся видимым, а доступ к данным проверяют реальные PEK endpoints и company membership. Явный список без `PEK_VIEW` скрывает раздел.
- Production mocks не добавлялись. Инвентарные и остальные запросы идут через общий реальный API-клиент.

## Проверенный контракт и несоответствия

Источником проверки служила локальная копия Java backend в `.audit-pek/eco-master/src/main/java/kz/eco/`. Это не подтверждение версии развёрнутого сервера.

| Область | Фактический контракт | Исправление / ограничение |
|---|---|---|
| Точки | `PekProgramSectionDtos.MonitoringPointRequest(name, coordinates, description)` | Убраны latitude/longitude из request type и исходящего payload |
| Реестры | `/api/pek/programs/{id}/emission-sources`, `discharge-sources`, `waste-items`; GET/POST, PUT/DELETE `/{rowId}` | Поля сверены с DTO; update/delete передают If-Match |
| Движение отходов | `/api/pek/reports/{id}/waste-movements`; GET/POST, DELETE `/{rowId}` | POST выполняет upsert по wasteItemId; существующая строка требует If-Match |
| Связи позиции | `monitoringPointId`, `emissionSourceId`, `waterOutletId`, `wasteSourceId` | Названия полей backend сохранены; UI выбирает записи соответствующих реестров |
| Готовность | Отдельный endpoint, `progressPercent`, `issues`; блокирующая ошибка имеет `severity: ERROR, blocking: true` | Ранее обзор не вызывал endpoint, а компонент ожидал severity BLOCKING; теперь используется серверный blocking |
| Сдача | POST `/api/pek/reports/{id}/submit` без request body; статус и серверное submittedAt | Backend не сохраняет пользовательские реквизиты; UI не отправляет выдуманные поля |
| Права | `UserResponse` содержит companyPermissions, но не permissions ПЭК; ресурсы имеют availableActions | Общие действия и доступ ПЭК без явных permissions закрыты. COMPANY_* не подменяют PEK_* |

## Блокеры и ограничения

1. **Реквизиты официальной сдачи не поддержаны backend.** Дата сдачи, регистрационный номер, способ, подтверждающий файл и комментарий показаны в форме как недоступные с объяснением. Их полноценное сохранение и повторное открытие невозможно без изменения API. Ручной переход статуса остаётся доступным по серверному `availableActions.submit`.
2. **Backend не предоставляет общие permissions ПЭК в UserResponse.** Просмотр раздела не блокируется при отсутствии этого необязательного поля: фактический доступ и область компаний проверяет backend. Для безопасного включения создания программ/отчётов и других действий без существующего ресурса всё ещё нужен явный серверный контракт прав. Возвращать role-based fallback нельзя по условию задачи.
3. **Нет проверки на авторизованном развёрнутом backend.** Сквозной сценарий «предприятие → объект → программа → разрешение → мониторинг → источники/точки/отходы → позиции/план → протоколы → превышения/мероприятия → отчёт → документы → подпись → сдача» проверен по маршрутам, компонентам и контрактным тестам, но не выполнен целиком с реальной учётной записью, файлами и ЭЦП. Сохранение/повторное открытие координат проверено UI-тестом с подменой API только в тестовой среде.
4. Общий набор тестов содержит четыре ошибки существующего модуля документооборота, вне изменённого ПЭК. Эти файлы не менялись.
5. Responsive обеспечен существующей адаптивной сеткой, диалогами и горизонтальным скроллом таблиц; визуальный прогон ПЭК на реальном стенде не выполнен. Проверка гидратации production build относится к публичным страницам, а не доказывает работу авторизованного ПЭК.
