# ПЭК: аудит frontend-контракта

Дата аудита: 2026-08-05.

## Источник истины и доступность OpenAPI

Проверены текущая frontend-реализация, `docs/pek-backend-integration-report.md` и доступные локальные адреса OpenAPI.

| Адрес | Результат |
| --- | --- |
| `http://localhost:4173/api/v3/api-docs` | `401 Unauthorized` |
| `http://localhost:4173/v3/api-docs` | HTML приложения Vite, не OpenAPI |
| стандартные Swagger URL на `localhost:8080` | сервис недоступен |

Защищённая актуальная схема без backend-сессии не получена. Поэтому в production-код не добавлены предполагаемые endpoint, enum или DTO. Последний подтверждённый локальный контракт — результат аудита Java-кода от 2026-07-31 в `docs/pek-backend-integration-report.md`.

## Существующий пользовательский путь

1. Пользователь открывает сводку ПЭК.
2. Создаёт программу через мастер из шести шагов.
3. Новая программа до финального POST хранилась только локально; серверный autosave работал только для существующей программы.
4. В карточке программы доступны данные, документы, история и workflow из `program.availableActions`.
5. Отчёт создаётся через creation-context; раньше по умолчанию выбирался первый квартал и был включён немедленный сбор.
6. Рабочая область отчёта содержала обзор и ссылку на общий список потенциально подходящих протоколов.

## Подтверждённые HTTP boundary

Единственный API-модуль: `src/features/pek/api/pekService.ts`. Используются только:

- `/api/pek/dashboard`;
- lookups assignees и object permits;
- CRUD/draft/documents/history/workflow программ;
- список, creation-context, создание, сбор и workflow отчётов.

Request/response преобразования централизованы в `mappers/programMappers.ts`, `mappers/reportMappers.ts` и `mappers/responseMappers.ts`. Production mock transport отсутствует.

## Расхождения и блокирующие backend gaps

Подтверждённый `ReportResponse` не содержит `availableActions`, readiness, source rows, plan/fact, unmatched/ambiguous/stale, exceedances, corrective actions, documents или history. Endpoint для этих ресурсов в подтверждённом контроллере отсутствуют. Также отсутствуют report return/edit, review comments, export и signing.

Из-за этого frontend не может безопасно реализовать:

- сбор как кнопку, управляемую `report.availableActions`;
- полноценные таблицы plan/fact и источников;
- ручное сопоставление и исключение источника;
- превышения и корректирующие мероприятия;
- backend readiness и переход к конкретной блокирующей строке;
- возврат отчёта с комментарием и полную историю отчёта.

Вкладки рабочего места для этих областей показывают честные пустые состояния и не вызывают придуманные API.

## Локальные DTO и OpenAPI

Типы сосредоточены в `api/pekContracts.ts`. Они отражают последний подтверждённый Java-контракт, но строковые поля `controlType`, `frequencyType`, `comparisonType`, `currency`, `status` не имеют подтверждённых enum/catalog endpoint. Поэтому замена всех полей на Select с выдуманными значениями не выполнена. `PekReadiness` остаётся не подключённым типом и не используется для локального вычисления готовности.

## Удалённые fallback permissions

Ранее `src/config/permissions.ts` выдавал все `PEK_*` права по ролям `ADMIN`, `DIRECTOR`, `HEAD`, `ECOLOGIST`, `LABORATORY` и другим, если `user.permissions` отсутствовал. Это позволяло показать действие, которое могло завершиться `403`.

Теперь `view_pek`, `edit_pek` и `PEK_*` разрешения принимаются только из auth DTO. Роль сотрудника не является заменой backend capability. Workflow программы дополнительно определяется только `program.availableActions`.

## Скрытые обязательные поля и validation

До изменения переход с шага контрольных позиций проверял только код и название. Схема не требовала `controlType`, `frequencyType`, единицу и способ сравнения; `PER_EVENT` не требовал `plannedCount`; RANGE не проверял `min <= max`.

Проверки добавлены в единую Zod-схему и пошаговую навигацию. Значение `0` проверяется через `null`/`undefined`, поэтому остаётся валидным.

## UX-проблемы, исправленные в этой итерации

- первый черновик теперь создаётся на сервере после минимальных сведений;
- кнопка «Сохранить черновик» доступна на каждом шаге;
- локальный draft остаётся аварийной копией, scoped по user/entity/company/version;
- текущий квартал выбирается автоматически;
- сбор при создании отчёта больше не включён без явного выбора;
- dashboard показывает `Нет данных` для `null`, а не фиктивный ноль;
- dashboard ориентирован на задачи и все подтверждённые метрики;
- общий список потенциальных протоколов больше не выдаётся за сохранённые sources;
- технические слова `backend`, `DTO`, `autosave` удалены из основных пользовательских состояний изменённых экранов.
