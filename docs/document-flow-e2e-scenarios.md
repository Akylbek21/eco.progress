# E2E-сценарии

Основной сценарий: системный администратор выдаёт доступ → владелец добавляет сотрудника по email → создаёт документ → загружает файл → создаёт маршрут → backend подготавливает и отправляет документ → внутренний сотрудник подписывает через NCALayer → внешний подписант открывает opaque token, получает challenge/file и подписывает → документ становится SIGNED → пользователь скачивает signed ZIP → архивирует с причиной и актуальной version.

Негативные сценарии: сбой после каждого checkpoint; повтор с тем же idempotency key; 401/403; исчерпанный лимит; 409 version conflict без auto-retry; неизвестный status (read-only); просроченный/использованный public token; отказ NCALayer; отклонение CMS; дубль БИН; контрагент используется документом.
